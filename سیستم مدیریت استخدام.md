# سیستم مدیریت استخدام (Restaurant Reservation System)

سیستم مبتنی بر Microservice برای مدیریت کاربران، رزروهای رستوران و اعلان‌ها، پیاده‌سازی‌شده با ASP.NET Core، gRPC، PostgreSQL و Docker.

## معماری پروژه

پروژه شامل سه Microservice مستقل است که هرکدام دیتابیس PostgreSQL جداگانه‌ی خود را دارند و از طریق **gRPC** با یکدیگر ارتباط برقرار می‌کنند. هر سرویس با معماری لایه‌ای (Domain / Application / Infrastructure / Api) و رویکرد DDD پیاده‌سازی شده است.

```
┌───────────────────┐        gRPC (UserExists)        ┌───────────────────┐
│  Identity Service  │ <─────────────────────────────  │  Employee Service  │
│  (User Management) │                                  │ (Reservation Mgmt) │
└─────────┬──────────┘                                  └─────────┬──────────┘
          │                                                        │
     identity-db                                              employee-db
     (PostgreSQL)                                              (PostgreSQL)
                                                                    │
                                                          gRPC (SendNotification)
                                                                    │
                                                                    ▼
                                                       ┌────────────────────────┐
                                                       │  Notification Service  │
                                                       └────────────┬───────────┘
                                                                    │
                                                             notification-db
                                                              (PostgreSQL)
```

- **Identity Service**: مدیریت کاربران سیستم (ایجاد، دریافت اطلاعات، دریافت لیست).
- **Employee Service**: مدیریت رزروهای رستوران؛ قبل از ثبت هر رزرو، از طریق gRPC وجود کاربر در Identity Service بررسی می‌شود.
- **Notification Service**: ثبت اعلان‌ها؛ پس از ایجاد موفق یک رزرو، Employee Service یک رویداد اعلان از طریق gRPC برای این سرویس ارسال می‌کند. در صورت در دسترس نبودن این سرویس، عملیات ثبت رزرو Rollback نمی‌شود و فقط خطا Log می‌شود.

## تکنولوژی‌ها

| فناوری | استفاده |
|---|---|
| ASP.NET Core 8 | فریمورک اصلی هر سرویس |
| Entity Framework Core | ORM و مدیریت Migration |
| PostgreSQL | دیتابیس مستقل هر سرویس |
| gRPC | ارتباط بین‌سرویسی |
| Docker / Docker Compose | Containerization و اجرای یکپارچه |
| Swagger (Swashbuckle) | مستندسازی API |
| FluentValidation | اعتبارسنجی ورودی‌ها |

## پیش‌نیازها

فقط **Docker** و **Docker Compose** کافی است. نیازی به نصب PostgreSQL یا انجام تنظیمات دستی نیست.

## نحوه اجرا

```bash
git clone <repository-url>
cd RestaurantReservation
docker compose up --build
```

پس از اجرا، Migration های EF Core به‌صورت خودکار روی هر دیتابیس اعمال می‌شوند (در `Program.cs` هر سرویس با `dbContext.Database.Migrate()` هنگام Startup).

## آدرس سرویس‌ها

| سرویس | REST / Swagger | gRPC |
|---|---|---|
| Identity Service | http://localhost:5001/swagger | localhost:6001 |
| Employee Service | http://localhost:5002/swagger | — |
| Notification Service | http://localhost:5003/swagger | localhost:6002 |

## اسکیمای Response API ها

تمام API ها از یک ساختار Response استاندارد پیروی می‌کنند:

**پاسخ موفق:**
```json
{
  "success": true,
  "data": { },
  "errors": null
}
```

**پاسخ خطا:**
```json
{
  "success": false,
  "data": null,
  "errors": [
    { "field": "GuestsCount", "message": "GuestsCount باید بزرگتر از صفر باشد." }
  ]
}
```

**پاسخ Pagination (لیست‌ها):**
```json
{
  "success": true,
  "data": {
    "items": [ ],
    "pageNumber": 1,
    "pageSize": 10,
    "totalCount": 42,
    "totalPages": 5
  },
  "errors": null
}
```

خطاهای غیرمنتظره (Exception) توسط یک Global Exception Middleware گرفته می‌شوند و در قالب `ProblemDetails` سازگار با ساختار بالا برگردانده می‌شوند؛ کد وضعیت HTTP متناسب با نوع خطا تنظیم می‌شود (مثلاً 404 برای NotFound، 400 برای Validation، 500 برای خطاهای داخلی).

## خلاصه API های هر سرویس

### Identity Service
| Method | Endpoint | توضیح |
|---|---|---|
| POST | `/api/users` | ایجاد کاربر |
| GET | `/api/users/{id}` | دریافت اطلاعات کاربر |
| GET | `/api/users?pageNumber=&pageSize=` | دریافت لیست کاربران |

### Employee Service
| Method | Endpoint | توضیح |
|---|---|---|
| POST | `/api/reservations` | ایجاد رزرو |
| PUT | `/api/reservations/{id}` | ویرایش اطلاعات رزرو |
| GET | `/api/reservations/{id}` | دریافت اطلاعات رزرو |
| GET | `/api/reservations?pageNumber=&pageSize=&fromDate=&toDate=&status=` | دریافت لیست رزروها با Pagination/Filtering |
| PATCH | `/api/reservations/{id}/preferences` | بروزرسانی Preferences |

### Notification Service
| Method | Endpoint | توضیح |
|---|---|---|
| GET | `/api/notifications/{id}` | دریافت اطلاعات یک اعلان |
| GET | `/api/notifications?userId=&pageNumber=&pageSize=` | دریافت لیست اعلان‌های یک کاربر |

اعلان‌ها همچنین از طریق متد gRPC داخلی `SendNotification` توسط سایر سرویس‌ها ثبت می‌شوند (این متد public نیست و فقط بین سرویس‌ها استفاده می‌شود).

## متغیرهای محیطی (Environment Variables)

تمام تنظیمات از طریق Environment Variable در `docker-compose.yml` تزریق می‌شوند:

| متغیر | توضیح |
|---|---|
| `ConnectionStrings__DefaultConnection` | کانکشن استرینگ PostgreSQL |
| `ASPNETCORE_ENVIRONMENT` | محیط اجرا (Development/Production) |
| `ASPNETCORE_URLS` | پورت REST داخلی کانتینر |
| `Grpc__Port` | پورت gRPC (برای سرویس‌های دارای سرور gRPC) |
| `Grpc__IdentityServiceAddress` | آدرس gRPC سرویس Identity (در Employee Service) |
| `Grpc__NotificationServiceAddress` | آدرس gRPC سرویس Notification (در Employee Service) |

## نکات فنی

- هر سرویس دیتابیس PostgreSQL مستقل خود را دارد و Migration ها به‌صورت خودکار روی همان دیتابیس اعمال می‌شوند.
- فیلد `Preferences` در Employee Service به‌صورت `jsonb` در PostgreSQL ذخیره می‌شود.
- ارتباط بین سرویس‌ها (بررسی وجود کاربر، ارسال اعلان) از طریق gRPC روی HTTP/2 انجام می‌شود.
- عدم دسترسی به Notification Service باعث Rollback عملیات ثبت رزرو نمی‌شود؛ فقط خطا در Log ثبت می‌شود.
